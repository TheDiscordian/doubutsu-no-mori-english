# Native designs and herabuna integration

## Installed content

The current name resources add 74 complete formerly Japanese fields and correct
one inherited `brook trout` field to the native `herabuna` species. Twenty-one
original source-bound approvals retain N64 designs, and four exact GameCube
matches resolve the reversed placed/carried gym-clothing labels. Eighteen
complete names also fit native short storage. The wider resource contains
4,536 English fields; eight accented name fields remain.

The two native herabuna messages preserve every original command and argument,
including page boundaries and the tournament continuation. General string
`021A` and the 352-word dynamic-letter resource use the same corrected species.
Only that one word changes; other source-word rows and native capture fields
remain unchanged. The [specification](../../specs/DESIGN_ITEM_NAMES.md) records
source identity, design evidence, exact resource coupling, and acceptance scope.

## Runtime integration and verification

The creator uses a compile-time immutable word profile. Its native initializer
checks the selected complete digest before publishing source pointers. The
artifact validator also resolves the actual MIPS digest argument, so matching
Python metadata cannot conceal an initializer compiled for the wrong resource.

Eight corrected-profile host C tests pass in 0.759 seconds, and the same eight
pass under address/undefined-behaviour sanitizers in 2.697 seconds. They execute the
actual digest and capture code, verify all 352 full words and name aliases,
reject modified/self-rehashed resources and the independently valid old profile,
and capture `herabuna` through both local and foreign letter preparation. Ordered
capture, full padding, invalid input, staging preservation, and inactive adapter
forwarding remain checked. These host fixtures do not establish native cartridge
execution, complete normal letter delivery, or hardware compatibility.

Three name/source/builder tests and six article tests have passing results;
the six article tests also pass under address/undefined-behaviour sanitizers.
The complete creator and ROM rebuild succeed with the corrected profile. Default
profile recompilation reproduces the entire prior creator image, symbols, and
relocations; all seven original-profile host capture tests pass. Current source
and artifact tests pass all ten cases in 28.693 seconds. They check the complete
ROM/UPS reconstruction, exact source
commands, declared/embedded/actually referenced digest agreement, rejection of a
stale initializer even with updated metadata, source-provenance restrictions,
and exactly 74 new credited name IDs under the unchanged source denominator.
The creator retains all 58,144 image bytes and 848 relocation bytes; only the
selected read-only digest, one word row and its resource digest, and article
data change. Its executable instructions, symbols, and relocation data remain
unchanged.

The full ROM differs in nine DMA entries: message/general-string data and tables,
native/wider item names, creator data, resident CRC configuration, and the DMA
table itself. The DMA-table entry at `00019D40` changes physical offsets after
the shorter message bank; it is not the main code file. Only message IDs `10F7`
and `1328`, and general string `021A`, differ from their preceding bank contents.

The native batch completes in `build/smoke-design-items-02`, from the 410-action
`build/design-items-scenario.json`. All 137 calls and 129 assertions pass in
411 result records, including the ordinary sixteen-byte string loader for
herabuna. The plan covers the new unique wide-name identities, eighteen short
fields, and shared loader boundaries. Complete buffers, heap/stack guards,
checkpoint restoration, blank Flash/Pak saves, disabled audio/screenshots,
and graceful shutdown pass. One frozen-result test verifies every call and
declared assertion without replaying the batch. Two frozen preceding-name
evidence tests also pass in 0.407 seconds without replay. The first
attempt stops before emulation because Xvfb is absent from PATH; the second uses
the existing binary under `~/Games/OpenRSC/headless/vendor/usr/bin/Xvfb` explicitly.
Do not repeat completed cases or treat the initial pre-fix design pilot as native
validation evidence.
